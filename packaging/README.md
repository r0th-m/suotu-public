# packaging —— 应急便携包启动脚本模板

`启动.bat` 是 Windows 应急便携包(go-pack / field-pack)的一键启动器,
打包时原样拷到包根目录。

## 字节级要求(改前必读)

- **GBK 编码**:现场机控制台默认代码页是 936(GBK);
- **CRLF 换行**:cmd 批处理解析器在 LF-only + 多字节字符下行边界错位,
  会把注释行拦腰截断、把残余文本当命令执行;
- **`chcp 936` 必须是第一条非 ASCII 之前的命令**(第 2 行):
  防止默认代码页非 936(如开了 UTF-8 全局支持的机器是 65001)时
  中文注释被错码页解析;
- **禁止 Linux 语法**:`>/dev/null` 在 cmd 下是「系统找不到指定的路径」;
- 改完必须字节校验(`xxd` 看 `0d 0a`、无 `/dev/null`)+ cmd 干跑验证;
- 本文件由 `.gitattributes` 的 `-text` 保护,git 不会改它的字节。

## 修复记录

### 2026-08-31 启动脚本修复

症状:现场机运行便携包报大量「'盘包内'不是内部或外部命令」
(注释行「rem 数据全部留在 U 盘包内 data\(...)」被截断执行),
以及「系统找不到指定的路径」。

根因(均为写文件时的 Linux 习惯污染):

1. bat 全文是 Unix LF 换行 → cmd 解析错位(已精确复现);
2. `chcp 936` 排在中文注释之后 → 非 936 默认码页的机器解析错码;
3. 历史版本(2026-08-05 打包)含 `>/dev/null`。

修复:重写为 GBK + CRLF + `chcp 936` 前置,逐字节验证,
suotu-go-pack / suotu-field-pack / wininfosc-go-pack 三包同步,
zip 全部重建并做解压冒烟验证。
