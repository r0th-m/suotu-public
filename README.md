# 索图（SuoTu）

> 面向应急响应的**应用层日志分析工作台**——按图索骥：日志就是那张图。
> Web 访问日志 / 中间件日志 / 业务应用日志，拿来即查，查完封存就走。

索图是**本地、离线优先、人主导**的日志分析平台：拿到一批日志（导出的、现场拷的），
导入 → 归一化 → 四层漏斗分析 → 人审定线索 → 一案可封存。
**它是分析平台，不是日志平台**：无采集端、无 agent、不做实时接入、不做长期留存、
不做多租户看板——绝不滑向 SIEM。

## 核心铁律

1. **判断权归人**——规则/AI 的产物一律进候选待审区，永不自动落线索；人点入库才算数
2. **确定性内核 + LLM 边缘**——签名匹配、统计聚合、归一化是确定性的先跑；AI 只做播种窗口内的精读，永远可关
3. **证据链不可断**——日志原文只读金库留存（SHA256 锚定）；每条判断锚到「日志源 + 行号 + 哈希」；审计哈希链
4. **一案可封存**——一次分析 = 一个可归档、可交接、可独立校验的包
5. **事件是原子，不是元素**——一行（或一个多行块）= 一个事件，原文完整保留，只抽索引/聚合字段；严禁拆元素再匹配（笛卡尔积爆炸，已实证失败）

## 项目亮点

### 四层漏斗（替代「均匀切片盲扫」）

```
L1 确定性全量扫描(零 AI):签名规则 + 统计聚合 + IOC 匹配 → 可疑锚点
L2 锚点播种:围着锚点切窗口(可疑段/异常时间窗),边界自动重叠
L3 AI 精读(map-reduce):只在播种窗口上跑,综合 pass 串跨片故事
L4 候选待审区:一切产物待审,人审入库;「无异常」须三重否定留痕
```

全量盲扫的 token 消耗永远不发生；无 AI 档（offline_lite）诚实降级可用。

### 键值比对算子族（实战狩猎模式固化）

统计规则不是死签名，是可参数化的比对算子（YAML 数据文件，人可审可换）：

- **同键异值分化**——同路径+IP+UA，跨方法返回长度/状态显著分化（0day 狩猎模式）
- **异键同值聚簇**——稀有 UA 跨多 IP 复现 = 疑似同源（稀有度门槛+爬虫排除 KB+概率标注，永不写「同一攻击者」）
- **同键变率突刺**——单键速率/分布随时间突变（z-score）
- **同键尺寸离群**——同路径+方法+状态码，响应字节偏离组内中位数超阈值（尺寸异常顶出语义事件）
- **链式 motif**——同键 A→B 时间窗链（认证失败潮→窗内成功 = 爆破成功链；ts_utc 缺失的源如实跳过）
- **周期信标**——同键规律间隔请求（变异系数+样本数+跨度三重闸；心跳/监控也周期，弱信号交人）
- **跨源实体联动**——同一公网实体出现在 ≥2 个日志源自动串联（私网/账户实体结构性排除，防张冠李戴）

规则治理三件套：**自定义规则入口**（draft→review→enable，内置只读不可覆盖，保存即过 schema 闸）、**预算帽**（每规则每案命中上限，超限截断如实标注）、**扫描轮次**（每次扫描记一轮，候选命中带轮次徽标，可按轮次过滤复盘）。

### 格式治理（业务日志繁星的工程答案）

- 入库三段式：**指纹探测给建议（置信度+抽样预览）→ 人确认或手选 → 描述文件兜底**
- 自定义格式 = YAML 描述文件（regex/json/csv + field_map + 多行合并 + 编码声明），
  **draft→review→enable 治理链，外部导入恒 draft 永不自动启用**
- **AI 辅助起草**：抽样给 AI 出草稿，人审后才生效（草稿不落盘）
- 出厂 11 个描述文件（catalina×2/logback/log4j/通达 OA×4/Yii 等，GBK 族齐全）

### 真实源还原（XFF）

nginx combined 追加段形如 IP 列表时自动抽为独立 `xff` 字段——站点挂在云防线/WAF
后面时，首列 IP 是回源节点，真实客户端在 XFF 里，字段检索直达。
内置检查器 UA 归因提示规则（命中即提醒「别把中间人当攻击者」）。

### 补充证据

应急响应中人会不断补材料（EDR 日志、防火墙导出、会话录屏）：上传时勾
「补充证据」，打标留痕、与日志源同管线——确认格式→解析→全文可检索。

### 单一检索层

前端搜索框、规则引擎、统计聚合、AI 工具走**同一个 query 模块**——
AI 能看到的东西和人看到的东西结构性一致，不存在「分析能查到、AI 查不到」的暗门。

### 证据链工程

原文只读金库 + SHA256 读前校验 + 行号锚点 + 审计哈希链 + 封存独立校验
（校验器是纯函数，脱离平台也能验包）。

### 记录区（案件日志流）

扫描轮次、AI 分析、人工笔记在同一条时间轴上合流：自动条目如实转述台账，
人工笔记可挂锚点一键跳回候选/轮次/AI 报告/原文行——案件的判断过程可回放。

### 原生支持 Windows 事件日志（evtx）与关联强度排序

- `.evtx` 直接上传解析（双通道：归一字段 + 原文锚点），不用先转文本；
- 跨源命中带 PageRank 式关联强度分（稀有度 × 频次，全确定性），
  AI 精读优先看强关联锚点——大日志量下不平均使力。

### 性能

- 并行解析（进程池，行区间切分，单行安全格式自动启用）：894MB / 469 万行
  nginx 日志实测 **45.5 秒**（同机串行 318.9 秒，7.0×）；派生数据并行/串行
  逐条相等（断言级测试焊死）。
- 5.7GB / 4894 万行混合业务日志压测：解析 823 秒，LIKE 全文检索按字节线性
  （5.97s/6.7GB），字段条件过滤亚秒。
- 诚实边界：多行合并格式（Java 堆栈类）与 CSV/IIS 带头格式走串行
  （跨行状态不可切），`SUOTU_PARALLEL_WORKERS=1` 可整体回退串行。

## 安全声明（请先读我）

- **本工具仅用于获得授权的安全分析、应急响应与取证场景。** 使用者须确保对分析
  对象拥有合法授权；作者不对任何滥用行为承担责任。
- **数据不出机**：全部数据（案件库/金库/账号）存于运行目录 `data/`，无遥测、
  无回传、无第三方分析服务。
- **AI 外发是唯一的数据出口，且有三道闸**：①在线厂商首次保存配置必须显式勾选
  「案件数据将发送至第三方模型服务」（落库留痕，审计可溯）；②任何案件可单独
  设置「禁止 AI 外发」（硬闸门，设置后该案在线调用一律被拒）；③使用本地
  Ollama 或 offline_lite 档（纯确定性，功能完整可用）则数据零外发。
- AI key 只落项目根 `.env`（不进库、不进审计、不打日志、不进响应体，接口只回
  掩码）。
- 默认账号口令请部署后立即更换；口令哈希 pbkdf2-sha256 20 万轮存储。
- 规则/统计/AI 的一切产出都是**候选**，不构成对任何主体的最终定性结论；
  平台不为你的研判背书——背书的是人。

## 部署方法

### 方式一：便携包（推荐现场使用）

解压即用，无需安装任何东西（自带绿色 Python 3.11，Windows 10/11 64 位）：

```
1. 双击 启动.bat(黑窗口保持开着,关窗=停服务)
2. 浏览器自动打开 http://localhost:8100
3. 首次使用在网页里创建管理员账号
```

数据全部留在包内 `data\`（U 盘即证据载体）；**拔盘前先关窗口**。

> **修复记录（2026-08-31）**：早期便携包的 `启动.bat` 因 Unix 换行符（LF）导致 cmd 解析错位（现场报「'XX' 不是内部或外部命令」），历史包还曾混入 Linux 语法 `>/dev/null`。启动脚本模板已纳入仓库 `packaging/启动.bat`（GBK + CRLF + 首行切码页，字节级校验），请勿手工改动其编码与换行符。详见 `packaging/README.md`。

### 方式二：源码部署（Windows/Linux）

```bash
# 后端(Python 3.11+)
pip install -r requirements.txt
uvicorn backend.app.main:app --port 8100        # 项目根目录下运行

# 前端开发模式(Node 18+)
cd frontend && npm install && npm run dev        # http://localhost:5173

# 前端生产模式(后端同端口托管)
cd frontend && npm run build                     # dist 由后端 :8100 直接托管
```

AI 配置（可选）：网页「AI 设置」里选厂商填 key（DeepSeek/OpenAI/通义/智谱/
Moonshot/Ollama 本地/自定义 OpenAI 兼容端点），在线厂商保存时需勾选外发同意。
不配就是 offline_lite 档，规则/统计/检索全功能可用。

主机取证互查（可选）：`.env` 配置 `TREE_COURT_URL/USER/PASS` 后，检索页可一键
反查「这个 IP/账户在主机取证侧哪些主机出现过」（只读互查，不写对端）。

## 使用流程（完整闭环）

```
① 建案件(一次应急 = 一个案件;不同事件的日志分开建案,别混)
② 日志源 tab → 上传(txt/log/zip)+ 填系统名/来源说明(补充证据勾选打标)
③ 看指纹建议(置信度+抽样预览)→ 人确认格式与时区 → 解析
   · 指纹只是建议,解析配置永远有人点头
   · 业务日志没有内置格式?→ 格式治理 tab 写描述文件,或让 AI 起草草稿
④ 规则与扫描 tab → 勾选要跑的规则(默认全选) → 运行扫描
   · 每次扫描记一轮(轮次台账),产出候选带轮次徽标
   · 自定义规则:draft→enable 治理,坏 yaml 不过闸;每规则命中预算帽防爆队列
⑤ 待审区 tab → 逐条裁决:接受为线索 / 排除(一切入库从这里过);可按轮次过滤
⑥ 检索 tab → 全文词 + 字段条件(IP/UA/方法/状态码/路径/XFF,精确或包含)
   + 时间窗;行号点击直达「查看」tab 原文
⑦ AI 分析 tab → 播种并精读(必须先有 pending 命中当锚点,
   无锚点不播种是设计,不是 bug)→ 报告区看综合推演,产出仍回待审区
⑧ 记录 tab → 扫描/AI 自动条目 + 人工笔记挂锚点,案件判断过程一条流回放
⑨ 收工 → 封存案件(zip 在 data/exports/,可离线校验)
```

## MCP 接入（Cherry Studio / Trae 等客户端直驾）

三步接入:

1. 索图顶栏「MCP 接入」→ 开启端点 → 签发 token(**明文只显示一次,立即复制**);
2. 在客户端的 MCP 配置里填(以 Trae 的 mcp.json 为例,Cherry Studio 同理选
   「Streamable HTTP / HTTP」类型):

```json
{
  "mcpServers": {
    "suotu": {
      "url": "http://127.0.0.1:8100/mcp",
      "headers": {
        "Authorization": "Bearer st_mcp_××××××××××(换成你刚签发的 token)"
      }
    }
  }
}
```

   远程命令型客户端的 `command/args` 写法不适用——我们是远程 HTTP 服务,填
   `url` + `headers`。若客户端报类型不支持,在 `suotu` 一段内加
   `"type": "http"`(部分版本写 `"streamableHttp"`)。
3. 直接问:「索图里有几个案件」「xxx IP 在这批日志里有什么活动」。

纪律(协议层写死):**只读**——不能上传/解析/改裁决/跑扫描;每次调用记审计链;
检索结果带行数上限与调用限频(30 次/分钟);每条响应都附「原文请回 Web 端
核对、最终裁决由人完成」的指引;token 可随时在面板吊销。现场便携包不含
MCP 模块(物理剔除,无此攻击面)。

## 常见问题

- **点了「播种并精读」没动？** 该源没有 pending 命中——先跑「规则与扫描」。
  L3 只在确定性筛出的可疑窗口上精读,不做全量盲扫。
- **AI 分析的结论在哪看?** 两处:AI 分析 tab 的报告区(过程+综合推演),
  待审区 tab(每条 finding 变成待裁决候选)。
- **解析报告里有坏行?** 如实计数+样例展示,不丢不猜。坏行多通常意味着
  格式选错或该日志有变体——换格式或写描述文件。
- **搜不到中文?** 内置三格式之外的 GBK 日志,用描述文件声明 `encoding: gbk`。
- **日志没识别出来格式?** 走 raw T0 兜底(原文可检索),然后写个描述文件。
- **大文件解析慢?** 确认是单行格式且 ≥16MB 才会自动并行;多行合并格式
  (Java 堆栈类)按设计走串行。`SUOTU_PARALLEL_WORKERS=1` 可回退全串行。

```

```
